# HabitFlow — Личный приватный трекер привычек, задач и продуктивности

**HabitFlow** — персональное веб-приложение для одного владельца, объединяющее ежедневные привычки, календарь выполнения, задачи с дедлайнами и статистику продуктивности. Приложение спроектировано для работы через единый URL с синхронизацией между ноутбуком и телефоном через общую серверную базу данных.

---

## 🔒 Безопасность и доступ единственного владельца

- **Никакой публичной регистрации:** в приложении существует только один владелец, задаваемый через переменные окружения (`OWNER_USERNAME` и `OWNER_PASSWORD_HASH` / `OWNER_PASSWORD`).
- **Защита всех маршрутов:** все страницы (`/`) и API (`/api/habits`, `/api/tasks`, `/api/stats/*`) закрыты серверной проверкой сессии. Неавторизованные запросы к API получают `401 Unauthorized`, а браузер перенаправляется на `/login`.
- **Криптостойкое хранение пароля:** поддерживается `PBKDF2-HMAC-SHA256` (260 000 итераций со случайной солью) и сравнение за константное время (`hmac.compare_digest`).
- **Защищённые Cookie и CSRF:** сессия хранится в подписанной `HMAC-SHA256` cookie `habitflow_session` с флагами `HttpOnly`, `SameSite=Lax` и `Secure` (в `production`). Все изменяющие запросы (`POST`, `PUT`, `PATCH`, `DELETE`) требуют заголовок `X-CSRF-Token`.
- **Защита от перебора пароля (Rate Limiting):** блокировка IP на 5 минут после 7 неудачных попыток входа.
- **Отключение публичной документации в Production:** при `APP_ENV=production` маршруты `/docs`, `/redoc` и `/openapi.json` автоматически отключаются.

## ✨ Основные функции

1. **Главная панель «Фокус на сегодня»:** сводка дня, чек-лист привычек, сегодняшние и просроченные задачи, индекс продуктивности.
2. **Привычки и серии (Streaks):** создание, редактирование, удаление привычек, расчёт текущей (`current_streak`) и лучшей (`best_streak`) серий, защита от дублей на одну дату (`UniqueConstraint`).
3. **Календарь за месяц:** тепловая карта (heatmap) месяца + таблица отметки выполнения привычек за любой прошедший день.
4. **Планировщик задач:** задачи с дедлайнами, приоритетами (`high`, `medium`, `low`) и статусами (`todo`, `in_progress`, `done`).
5. **Статистика за 7 и 30 дней:** графики динамики, лидерборд серий и структура задач.
6. **Адаптивный интерфейс (320px — 1440px+):** боковая навигация на ноутбуке и удобный фиксированный нижний таб-бар (`bottom-nav`) и `bottom-sheet` модальные окна на телефоне.
7. **Единый часовой пояс владельца (`OWNER_TIMEZONE`):** ноутбук, телефон и облачный сервер всегда используют одну и ту же дату «сегодня».

## 🔑 Генерация секретов владельца перед публикацией

Никогда не храните реальные пароли в коде. Перед деплоем сгенерируйте `SECRET_KEY` и `OWNER_PASSWORD_HASH` встроенной командой:

```bash
./.venv/bin/python -m app.auth --generate-secret --hash-password "Ваш_Сильный_Пароль"
```

Скопируйте полученные строки `SECRET_KEY` и `OWNER_PASSWORD_HASH` в `.env` (на VPS) или в раздел **Environment Variables** вашего облачного хостинга.

## ☁️ Деплой в интернет (Ноутбук + Телефон через один URL)

### Важное правило выбора базы данных при деплое:
- **Вариант А — Хостинг с постоянным диском (VPS, Docker Volume, Fly.io Volume, Render Paid Disk):**
  Можно использовать встроенный **SQLite** (в проекте уже включён режим `WAL` для параллельной работы с телефона и ноутбука). Укажите путь к примонтированному диску, например:
  `DATABASE_URL="sqlite:////data/habitflow.db"`
- **Вариант Б — Облачный хостинг с временной (эфемерной) файловой системой (Render Free, Railway, Koyeb):**
  На бесплатных контейнерах без диска локальные файлы стираются при перезапуске контейнера! Поэтому для такого деплоя подключите бесплатную облачную БД **PostgreSQL** (например, Neon.tech, Supabase или Render Postgres), добавьте драйвер `psycopg2-binary` в `requirements.txt` и задайте переменную:
  `DATABASE_URL="postgresql://user:pass@host:5432/dbname"`

### Команда запуска для Production:
```bash
uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000} --proxy-headers --forwarded-allow-ips='*'
```
В репозитории уже подготовлены [`Dockerfile`](Dockerfile), [`render.yaml`](render.yaml) и [`Procfile`](Procfile).

## 💾 Резервное копирование и восстановление базы данных

В проекте есть встроенная утилита [`scripts/backup_restore.py`](scripts/backup_restore.py):

1. **Экспорт всех данных (привычки, логи, задачи) в переносимый JSON-файл:**
   ```bash
   ./.venv/bin/python scripts/backup_restore.py --export-json backups/my_backup.json
   ```
2. **Восстановление (импорт) из JSON-файла без дублирования записей:**
   ```bash
   ./.venv/bin/python scripts/backup_restore.py --import-json backups/my_backup.json
   ```
3. **Горячая копия файла SQLite (`habitflow.db`):**
   ```bash
   ./.venv/bin/python scripts/backup_restore.py --sqlite-backup backups/habitflow_snapshot.db
   ```
